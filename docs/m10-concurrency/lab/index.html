Lab — Build PlatformOps v0.8: the Concurrent Health Checker

This lab has two parts. First you hand-build check_many_sequential() and check_many() -- a sequential baseline and a bounded thread-pool version of M9's check_health() -- wired into a new health-check-many CLI command. Then you extend it: an asyncio version with the same bounded concurrency, a batch-level deadline that cancels slow checks instead of waiting forever, and tests for all of it, specified precisely and handed to your coding agent the same way M6-M9 did.

You need ~/platformops from the M9 lab, already tagged v0.7, with uv run pytest -q passing.

1. Add check_many_sequential() and check_many()​

Open src/platformops/httpclient.py. Add this constant next to RETRYABLE_STATUS_CODES:

src/platformops/httpclient.py
# How many health checks run at the same time in check_many() and
# check_many_async(). Every service you might check has its own capacity --
# checking 200 endpoints with no cap means 200 simultaneous connections
# landing on whichever load balancers and DNS resolvers sit in front of
# them, which looks a lot like the outage you were trying to detect. 8 is a
# deliberately modest default a caller can override for a bigger fleet.
DEFAULT_MAX_CONCURRENCY = 8

Add from concurrent.futures import ThreadPoolExecutor to the imports at the top of the file, then add these four pieces below check_health():

src/platformops/httpclient.py
@dataclass
class HealthSummary:
    """The aggregated outcome of checking many URLs at once.

    `results` keeps every individual `HealthResult` in the same order the
    URLs were given -- a caller that needs the detail never has to
    re-correlate it. `ok` and `failed` are the two numbers you actually want
    on a terminal or in a CI log without scanning the whole list: how many
    of the fleet answered healthy, and how many did not.
    """

    total: int
    ok: int
    failed: int
    results: list[HealthResult]


def summarize_health_results(results: list[HealthResult]) -> HealthSummary:
    """Turn a list of `HealthResult` into the counts a report actually needs."""
    ok_count = sum(1 for result in results if result.ok)
    return HealthSummary(
        total=len(results),
        ok=ok_count,
        failed=len(results) - ok_count,
        results=results,
    )


def check_many_sequential(
    urls: list[str], *, timeout: httpx.Timeout | float = DEFAULT_TIMEOUT
) -> list[HealthResult]:
    """Check every URL one after another. The baseline every faster version is measured against.

    Total time is roughly the sum of every individual check's latency -- 50
    endpoints at ~200ms each is 10 seconds, even though each request spends
    almost all of that time waiting on the network, not doing CPU work. That
    wasted wait is exactly what check_many() and check_many_async() claw
    back by overlapping the waits instead of taking them one at a time.
    """
    return [check_health(url, timeout=timeout) for url in urls]


def check_many(
    urls: list[str],
    *,
    timeout: httpx.Timeout | float = DEFAULT_TIMEOUT,
    max_workers: int = DEFAULT_MAX_CONCURRENCY,
) -> list[HealthResult]:
    """Check many URLs concurrently using a bounded thread pool.

    Each check_health() call spends almost all of its time blocked on
    network I/O, not holding Python's GIL -- exactly the situation a thread
    pool is good at speeding up, even in CPython. max_workers caps how
    many requests are ever in flight at once.

    Returns results in the same order as urls, not completion order --
    executor.map() guarantees this, so a caller can zip the input list
    against the output without re-sorting by URL.
    """
    if not urls:
        return []
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        return list(executor.map(lambda url: check_health(url, timeout=timeout), urls))

2. Wire health-check-many into the CLI​

Open src/platformops/cli.py. Add check_many, check_many_sequential and summarize_health_results to the platformops.httpclient import, then add this command next to http_check:

src/platformops/cli.py
@app.command("health-check-many")
def health_check_many(
    ctx: typer.Context,
    urls: Annotated[
        list[str],
        typer.Argument(
            help="two or more URLs to check, e.g. https://a.example https://b.example"
        ),
    ],
    as_json: Annotated[
        bool,
        typer.Option(
            "--json", help="print machine-readable JSON instead of plain text"
        ),
    ] = False,
    mode: Annotated[
        str,
        typer.Option("--mode", help="sequential or threaded"),
    ] = "threaded",
    max_concurrency: Annotated[
        int,
        typer.Option(
            "--max-concurrency", help="how many checks run at once (threaded mode)"
        ),
    ] = DEFAULT_MAX_CONCURRENCY,
    timeout: Annotated[
        float,
        typer.Option("--timeout", help="seconds to wait for each endpoint's response"),
    ] = 10.0,
) -> None:
    """Check the health of many endpoints at once, reporting partial failures instead of stopping at the first one."""
    quiet = ctx.obj["quiet"]

    bad_urls = [url for url in urls if "://" not in url]
    if bad_urls:
        _fail(
            f"'{bad_urls[0]}' is missing a scheme -- did you mean 'https://{bad_urls[0]}'?",
            as_json=as_json,
            exit_code=2,
        )

    if mode not in {"sequential", "threaded"}:
        _fail(
            f"--mode must be sequential or threaded, got '{mode}'",
            as_json=as_json,
            exit_code=2,
        )

    if mode == "sequential":
        results = check_many_sequential(urls, timeout=timeout)
    else:
        results = check_many(urls, timeout=timeout, max_workers=max_concurrency)

    summary = summarize_health_results(results)

    if as_json:
        typer.echo(
            json.dumps(
                {
                    "status": "ok" if summary.failed == 0 else "error",
                    "mode": mode,
                    "total": summary.total,
                    "ok": summary.ok,
                    "failed": summary.failed,
                    "results": [
                        {
                            "url": result.url,
                            "ok": result.ok,
                            "status_code": result.status_code,
                            "latency_ms": result.latency_ms,
                            "error": result.error,
                        }
                        for result in results
                    ],
                },
                indent=2,
            )
        )
    else:
        if not quiet or summary.failed:
            typer.echo(f"{summary.ok}/{summary.total} healthy ({mode})")
        for result in results:
            if result.ok:
                if not quiet:
                    typer.echo(
                        f"  {result.url}: OK -- {result.status_code} in {result.latency_ms}ms"
                    )
            else:
                detail = result.error or f"status {result.status_code}"
                typer.echo(f"  {result.url}: FAIL -- {detail}")

    raise typer.Exit(code=0 if summary.failed == 0 else 1)

Also add DEFAULT_MAX_CONCURRENCY to the same platformops.httpclient import.

3. Add tests​

Add these to tests/test_httpclient.py -- monkeypatching check_health so these tests exercise only check_many_sequential()'s and check_many()'s own ordering and concurrency logic, never the network:

tests/test_httpclient.py
import threading
import time

from platformops.httpclient import HealthResult, check_many, check_many_sequential


def test_check_many_sequential_checks_every_url_in_order(monkeypatch):
    calls = []

    def fake_check_health(url, *, timeout=None):
        calls.append(url)
        return HealthResult(url=url, ok=True, status_code=200, latency_ms=1.0)

    monkeypatch.setattr("platformops.httpclient.check_health", fake_check_health)

    urls = ["https://a.example", "https://b.example", "https://c.example"]
    results = check_many_sequential(urls)

    assert calls == urls  # sequential means called strictly in order
    assert [result.url for result in results] == urls


def test_check_many_never_exceeds_max_workers_in_flight(monkeypatch):
    active = 0
    peak = 0
    lock = threading.Lock()

    def fake_check_health(url, *, timeout=None):
        nonlocal active, peak
        with lock:
            active += 1
            peak = max(peak, active)
        time.sleep(0.05)
        with lock:
            active -= 1
        return HealthResult(url=url, ok=True, status_code=200, latency_ms=1.0)

    monkeypatch.setattr("platformops.httpclient.check_health", fake_check_health)

    urls = [f"https://svc-{i}.example" for i in range(10)]
    check_many(urls, max_workers=3)

    assert 1 < peak <= 3  # genuinely concurrent, but never past the cap

5. Extend the client: hand this to your coding agent​

Three things remain:

  • An asyncio version of everything you just built -- check_health_async() and check_many_async(), with the same bounded concurrency but no thread pool underneath it.
  • A batch-level timeout (batch_timeout) that cancels every check still running once a deadline for the whole batch passes, reporting a cancelled check as a result instead of dropping it.
  • A --mode async option on health-check-many, plus a --batch-timeout option that only makes sense together with it.

Open your coding agent in the project folder:

Paste this request exactly as written:

has HealthResult, check_health(url, *, timeout=DEFAULT_TIMEOUT,
transport=None), check_many_sequential(urls, *, timeout=DEFAULT_TIMEOUT),

Troubleshooting
  • check_many results come back in a different order than the URLs you passed. executor.map guarantees input order, but only if you use executor.map, not [executor.submit(...) for ...] collected with as_completed() -- the latter returns results in completion order. Confirm check_many uses .map(...), not .submit(...).
  • health-check-many --mode async hangs instead of finishing. A missing asyncio.run(...) around the call to check_many_async from a synchronous CLI command is the usual cause -- check_many_async is a coroutine function; calling it directly returns a coroutine object, not a result, and nothing ever awaits it.
  • A batch_timeout test takes the full uncancelled duration instead of stopping early. Confirm asyncio.wait(..., timeout=batch_timeout, ...) is actually passed batch_timeout, and that task.cancel() is called on every task still in pending afterward -- a task that is never cancelled keeps running in the background even after the function returns.
  • check_many peaks at more concurrent requests than max_workers allows. Confirm ThreadPoolExecutor(max_workers=max_workers) is the value actually passed in, not a hardcoded number, and that the executor is not being created fresh inside a loop (which would remove the cap entirely).
  • The whole batch fails with a connection error against postman-echo.com or another live test endpoint. Public test services occasionally throttle or degrade -- rerun the command once, and if it is still failing, temporarily swap in https://example.com (no artificial delay, but reliably up) to confirm the code itself works before blaming the network.
  • A mocked async test in test_httpclient.py seems to hang instead of finishing instantly. Confirm the test wraps its coroutine in asyncio.run(...) and that @respx.mock (or the monkeypatched check_health_async) is actually active for that test -- a real network call inside an unpatched async test will run at real network speed, not instantly.

Teardown​

Nothing in this lab starts a service, a container or a cluster -- every call this module makes is a short-lived HTTP request that closes itself. There is nothing to stop.

cd ~
rm -rf platformops

Run that only if you want to remove the project and rebuild it from the checkpoint. Otherwise, keep ~/platformops; it carries forward into every later module.

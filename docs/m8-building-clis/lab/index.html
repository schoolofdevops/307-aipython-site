Lab — Build PlatformOps v0.6: the PlatformOps CLI

This lab has two parts. First you hand-build platformops.cli -- a real Typer app with three commands, wired up as an actual installed command, platformops, not something you run with python -m. Then you extend it: --json output, global --quiet/--verbose, one shared error helper, and shell completion, specified precisely and handed to your coding agent the same way M6 and M7 did.

You need ~/platformops from the M7 lab, already tagged v0.5, with uv run pytest -q passing.

cd ~/platformops
git log --oneline -1

Expected output

a1b2c3d platformops v0.5 -- reliable validation and diagnostics

Your hash will differ -- the important part is the v0.5 tag and message.

2. Build platformops.cli​

Before wiring the version command, fix one small thing it would otherwise expose: src/platformops/__init__.py has always had __version__ = "0.0.0", hardcoded since M2, never updated even as pyproject.toml's version climbed to 0.5.0. Nothing has ever printed __version__ back to a user before, so nobody noticed. platformops version is about to print it, so it has to tell the truth. Fix the source, not the symptom -- read the version from the package's own install metadata instead of a second hand-maintained constant:

src/platformops/__init__.py
"""PlatformOps Toolkit — a Python operational toolkit for DevOps, platform
engineering and SRE work. This module grows release by release through the
course, from this v0.0 foundation to the v3.0 capstone.
"""

from importlib.metadata import PackageNotFoundError
from importlib.metadata import version as _installed_version

try:
    # Read the version from the package's own install metadata -- the same
    # metadata `uv sync` writes from pyproject.toml's `version =` line. One
    # source of truth: bump pyproject.toml, run `uv sync`, and every place
    # that reports a version (this constant, `platformops version`) picks
    # up the new number without a second place to edit.
    __version__ = _installed_version("platformops")
except PackageNotFoundError:  # pragma: no cover -- running from a bare checkout, never installed
    __version__ = "0.0.0"


def about() -> str:
    """Return the toolkit's one-line tagline.

    This is the smallest possible piece of the toolkit: a function you can
    import, call and test. Every later module adds real capability next to
    it — the shape (a tested function in this package) does not change.
    """
    return f"PlatformOps Toolkit v{__version__} — inspect, validate and troubleshoot your services"


def main() -> None:
    print(about())

Now the CLI itself. Create src/platformops/cli.py:

src/platformops/cli.py
"""platformops.cli -- the `platformops` command.

Every capability this toolkit has built so far was a function you had to
import into a Python shell, or a module you ran with `python -m`. Real
operators do not want either -- they want one command, `platformops`, with
sub-commands underneath it, `--help` that explains itself, and exit codes a
CI job can trust. Typer builds that command from plain, type-hinted Python
functions: this module IS the CLI, and it is also still an importable,
testable module like every other one in this package.
"""

from pathlib import Path
from typing import Annotated

import typer

from platformops import __version__
from platformops.config import ConfigError, load_yaml_dict
from platformops.inventory.report import print_report
from platformops.servicedef import ServiceDefinition, validate_service

app = typer.Typer(
    name="platformops",
    help="Inspect, validate and troubleshoot your services from one command line.",
    no_args_is_help=True,
)


@app.command()
def validate(
    path: Annotated[Path, typer.Argument(help="path to a service definition YAML file")],
) -> None:
    """Validate a service definition file.

    Wraps the same loader and validator `platformops.diagnostics` uses
    (`load_yaml_dict` from M6, `validate_service` from M5) -- one validation
    path, whether you call it as a module or as this command.
    """
    try:
        data = load_yaml_dict(path)
    except ConfigError as exc:
        typer.echo(f"{path}: ERROR -- {exc}", err=True)
        raise typer.Exit(code=1)

    result = validate_service(data)

    if isinstance(result, ServiceDefinition):
        typer.echo(f"{path}: OK -- {result.to_summary()}")
        raise typer.Exit(code=0)

    typer.echo(f"{path}: FAIL")
    for error in result:
        field = ".".join(str(part) for part in error["loc"])
        typer.echo(f"  {field}: {error['msg']}")
    raise typer.Exit(code=1)


@app.command()
def inspect() -> None:
    """Print the infrastructure inventory report (the M3/M4 project)."""
    print_report()


@app.command()
def version() -> None:
    """Print the installed platformops version."""
    typer.echo(f"platformops {__version__}")


if __name__ == "__main__":
    app()

Three plain, type-hinted functions, one @app.command() decorator each. path: Annotated[Path, typer.Argument(...)] is what makes path a required positional argument instead of a --path option -- Typer reads the annotation, not just the name. no_args_is_help=True means running bare platformops (no command) prints help instead of doing nothing silently.

3. Wire the entry point​

Open pyproject.toml and change the [project.scripts] line:

pyproject.toml
[project.scripts]
platformops = "platformops.cli:app"

This one line is what turns platformops.cli.app into an installed command named platformops on your PATH. It replaced platformops = "platformops:main" -- the trivial one-line CLI M2 set up as a placeholder back when this project was brand new; you are not adding an entry point for the first time, you are pointing an existing one at real work.

5. Add tests​

Typer ships CliRunner, which calls your app in-process (no subprocess, no real terminal) and captures its exit code and output for you to assert on. Create tests/test_cli.py:

tests/test_cli.py
from typer.testing import CliRunner

from platformops.cli import app

runner = CliRunner()


def test_version_command_exits_0_and_prints_a_version_string():
    result = runner.invoke(app, ["version"])

    assert result.exit_code == 0
    assert "platformops" in result.stdout


def test_validate_a_good_file_exits_0_and_reports_ok(tmp_path):
    good = tmp_path / "service.yaml"
    good.write_text(
        "name: checkout-api\n"
        "repository: github.com/example/checkout-api\n"
        "environment: prod\n"
        "team_owner: payments-team\n"
        "kubernetes_namespace: checkout\n"
        "deployment_name: checkout-api\n"
        'aws_account: "111122223333"\n'
        "region: us-east-1\n"
        "observability:\n"
        "  dashboard_url: https://grafana.example.com/d/checkout-api\n"
        '  alert_channel: "#checkout-alerts"\n'
    )

    result = runner.invoke(app, ["validate", str(good)])

    assert result.exit_code == 0
    assert "OK" in result.stdout


def test_validate_a_bad_file_exits_1_and_names_the_field(tmp_path):
    bad = tmp_path / "service.yaml"
    bad.write_text("name: checkout-api\n")  # missing every other required field

    result = runner.invoke(app, ["validate", str(bad)])

    assert result.exit_code == 1
    assert "repository" in result.stdout


def test_validate_a_missing_file_exits_1_and_names_the_path(tmp_path):
    missing = tmp_path / "does-not-exist.yaml"

    result = runner.invoke(app, ["validate", str(missing)])

    assert result.exit_code == 1
    assert "not found" in result.output


def test_inspect_command_exits_0_and_prints_the_report():
    result = runner.invoke(app, ["inspect"])

    assert result.exit_code == 0
    assert "PlatformOps Inventory Report" in result.stdout

6. Extend the CLI: hand this to your coding agent​

Three things remain, and none of them are new commands -- they are cross-cutting behaviour every command should share:

  • --json on validate and inspect -- one parseable object per command, for a script or CI job.
  • Global --quiet / --verbose -- wired into M7's logging, plus a --quiet that silences a command's routine success line without ever hiding a real failure.
  • One shared error helper -- so every command's error path looks the same, instead of five commands each formatting their own.

Open your coding agent in the project folder:

claude

Paste this request exactly as written:

I'm working in this uv-managed Python project with a Typer CLI at
src/platformops/cli.py (app = typer.Typer(...), with @app.command()
functions validate(path), inspect() and version()). Please make these
changes without changing any existing passing behavior:

1. Add a `--json` boolean option to `validate` and `inspect`. On validate:
   a valid file prints {"status": "ok", "service": <the ServiceDefinition
   as a dict via .model_dump(mode="json")>} as indented JSON to stdout and
   exits 0; an invalid file (a data problem, not a file problem) prints
   {"status": "error", "errors": <the pydantic error list>} as indented
   JSON (use default=str for the json.dumps call, since pydantic error
   dicts can hold non-JSON-native values) and exits 1. On inspect: build a
   small dict from the existing platformops.inventory functions (data.
   INVENTORY, rules.count_by_environment, rules.find_missing_owner,
   rules.find_low_memory_prod, summary.build_summary) with keys
   total_servers, by_environment, missing_owner, low_memory_prod and
   summary, and print it as indented JSON when --json is passed, instead
   of calling print_report().

2. Add two mutually-exclusive global boolean options on the Typer app
   itself (a @app.callback() function taking a typer.Context, verbose and
   quiet): --verbose and --quiet. If both are passed, print
   "Error: --verbose and --quiet cannot be used together" to stderr and
   exit with code 2 (a usage error, distinct from a validation failure's
   exit code 1). Otherwise call logging.basicConfig(level=DEBUG if
   verbose else WARNING, format="%(levelname)s %(name)s: %(message)s",
   force=True) -- the force=True matters the same way it did in
   diagnostics.py and config.py. Store quiet on ctx.obj so validate can
   read it. Add a module-level `logger = logging.getLogger("platformops.cli")`
   and log at debug/info/warning the same way platformops.diagnostics
   already does. On validate, when the file is valid, --quiet suppresses
   the plain-text "OK -- ..." line (but never the --json output, which is
   unaffected by --quiet). --quiet must never suppress a FAIL report --
   only the "everything is fine" chatter on success.

3. Add one shared helper, `_fail(message, *, as_json, exit_code=1)`, that
   every command-level error (a ConfigError from validate, the
   --verbose/--quiet conflict) routes through instead of formatting its
   own typer.echo/raise typer.Exit pair. When as_json is True it prints
   {"status": "error", "error": message} to stdout; otherwise it prints
   "Error: {message}" to stderr. It always raises typer.Exit(code=exit_code).

4. Do not add any new third-party dependency -- everything above uses
   Typer (already a dependency) and the standard library.

5. Fix tests/test_foundation.py's test_version_is_pinned_to_v0_0 -- it
   asserts `__version__ == "0.0.0"`, a value that stopped being true the
   moment __version__ started reading from installed package metadata.
   Rename it to something like
   test_version_matches_the_installed_package_version and assert the
   value matches the pattern of a real version string
   (re.match(r"^\d+\.\d+\.\d+$", __version__)) instead of a literal that
   will go stale again next release.

6. Add tests to tests/test_cli.py covering: --json on a good and a bad
   validate call (parse the JSON, check the status field), --json on
   inspect (parse the JSON, check total_servers), --quiet suppressing the
   OK line on a good file, --quiet NOT suppressing a FAIL report, and
   --verbose combined with --quiet exiting 2. Every existing test must
   stay green.

7. Run `uv run ruff check .` and `uv run pytest -q` yourself before you
   finish, and tell me the result.

This spec names the exact function signatures and file already in the project (not "add JSON support somehow"), states the --quiet-never-hides-a-failure rule explicitly (the one detail easy to get backwards), and asks for the same self-verification every agent step in this course has asked for.

  • Does --quiet ever suppress a FAIL report? It must not -- only the success line. Read validate's body: the FAIL branch should print unconditionally, with no quiet check guarding it.
  • Does --json output change when --verbose or --quiet is also passed? It should not -- a script reading --json should get an identical object regardless of how chatty the human-facing logging is.

  • Did the agent add a dependency? pyproject.toml's dependencies list should show only pydantic, pyyaml and typer -- three entries, not four.
  • Is test_version_is_pinned_to_v0_0 still asserting a literal "0.0.0"? It should not be -- that was the bug. Confirm it was renamed and now checks the version string's shape.

Troubleshooting
  • command not found: platformops -- uv sync did not run after you changed [project.scripts], or you ran platformops directly instead of uv run platformops (or uv run python -m platformops.cli). uv run puts .venv/bin on PATH for that one command; a bare platformops outside uv run only works if you have separately activated the virtual environment (source .venv/bin/activate).
  • platformops --help still shows the old, empty command with no sub-commands -- this is a stale entry point. uv sync after editing [project.scripts] regenerates the installed console-script shim; if you skipped that step, the old platformops = "platformops:main" shim is still the one on your PATH. Re-run uv sync.
  • platformops version still prints 0.0.0 -- either the __init__.py fix from step 2 was not applied, or you ran the command from an interpreter that never uv sync-installed this project (a plain python3 -m platformops.cli outside the project's own .venv). Use uv run.
  • --json output has a trailing log line mixed into it -- that WARNING/INFO text comes from the logger, which writes to stderr by default; it only looks mixed in because your terminal shows both streams together. Redirect it away: platformops validate bad.yaml --json 2>/dev/null.
  • A test you did not touch starts failing after step 6 -- almost always test_version_is_pinned_to_v0_0, still asserting the literal "0.0.0" because the agent's edit did not reach it. Confirm it was renamed per the checklist in step 7.
  • --verbose --quiet together silently does one or the other instead of erroring -- the mutual-exclusion check in the @app.callback() function is missing or was placed after the logging.basicConfig(...) call instead of before it.

Teardown​

Nothing in this lab starts a service, a container or a cluster -- there is nothing to stop.

cd ~
rm -rf platformops

Run that only if you want to remove the project and rebuild it from the checkpoint. Otherwise, keep ~/platformops; it carries forward into every later module.

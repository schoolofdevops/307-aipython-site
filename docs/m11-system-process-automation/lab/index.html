Lab — Build PlatformOps v0.9: the Local Operations Adapter

This lab has two parts. First you hand-build local_ops.py -- git_status(), git_log() and docker_info(), each running a real external command safely -- wired into a new local-status CLI command. Then you extend it: a container_list() function that parses Docker's newline-delimited JSON, a safety audit across every subprocess.run() call in the file, a check-security command that scans the codebase for shell=True, and tests for all of it, specified precisely and handed to your coding agent the same way M6-M10 did.

You need ~/platformops from the M10 lab, already tagged v0.8, with uv run pytest -q passing.

cd ~/platformops
git log --oneline -1

Expected output

a1b2c3d platformops v0.8 -- Concurrent Health Checker

The commit hash will differ, but the message should name v0.8.

1. Add src/platformops/local_ops.py​

Create a new file, src/platformops/local_ops.py:

src/platformops/local_ops.py
"""platformops.local_ops -- run local commands the way production code has to.

Every capability platformops has built so far either worked on data already
in memory (the M3/M4 inventory), a file on disk (M6's service.yaml) or a
remote HTTP endpoint (M9's httpclient). A lot of real operational work
answers questions that only exist as the output of another program already
installed on the machine: is this repository's working tree clean, what did
the last few commits change, is the Docker daemon even reachable. Those
answers come from running `git` and `docker` as external commands, not from
a Python library that reimplements what they already do well.

`subprocess` is the standard library's way to run another program and get
its result back -- and it is also one of the easiest ways to make Python
automation genuinely unsafe. Every function in this file follows three
rules without exception: arguments are always passed as a list, never as a
shell string (`shell=True` is never used anywhere in this file); every call
has an explicit `timeout`, so a hung external command cannot hang this
process forever; and a command that fails, is missing, or is not installed
is reported back as data (a result with `error` set), never left to raise
an unhandled exception -- the same never-raises-for-normal-outcomes
contract `check_health()` established in M9 for an unhealthy HTTP
endpoint.
"""

from __future__ import annotations

import json
import logging
import subprocess
from dataclasses import dataclass

logger = logging.getLogger("platformops.local_ops")

# Every subprocess.run() call in this file uses this unless a caller passes
# its own value. 10 seconds is generous for a local `git` or `docker`
# command against a healthy machine, and short enough that a hung git
# process on a stale network mount, or a Docker daemon that never answers,
# cannot block a caller indefinitely.
DEFAULT_TIMEOUT = 10.0


@dataclass
class GitStatusResult:
    """The outcome of one `git_status()` call.

    `clean` and `changed_files` describe a normal, healthy answer: a
    working tree with nothing to report is just as valid an outcome as one
    with five changed files. `error` is set only when this call could not
    get an answer at all -- the path is not a git repository, the `git`
    binary is missing, or the command timed out -- never for a dirty tree,
    which is not an error at all.
    """

    repo_path: str
    clean: bool
    changed_files: list[str]
    error: str | None = None


def git_status(repo_path: str, *, timeout: float = DEFAULT_TIMEOUT) -> GitStatusResult:
    """Run `git status --porcelain` in `repo_path` and report the tree's state.

    `--porcelain` is git's stable, script-friendly status format -- one
    line per changed file, no headers, no colour codes to strip -- built
    for exactly this use, unlike the human-formatted plain `git status`.

    Never raises for "not a git repository" or a dirty tree -- both are
    normal outcomes reported in the returned `GitStatusResult`, the same
    never-raises-for-normal-outcomes contract `check_health()` established
    in M9. Only a missing `git` binary or a timeout is reported as an
    error a caller may want to act on differently.
    """
    logger.debug("checking git status in %s", repo_path)
    try:
        result = subprocess.run(
            ["git", "status", "--porcelain"],
            capture_output=True,
            text=True,
            timeout=timeout,
            cwd=repo_path,
            check=False,
        )
    except FileNotFoundError:
        logger.warning("git is not installed or not on PATH")
        return GitStatusResult(
            repo_path=repo_path,
            clean=False,
            changed_files=[],
            error="git is not installed or not on PATH",
        )
    except subprocess.TimeoutExpired:
        logger.warning("%s: git status timed out after %.1fs", repo_path, timeout)
        return GitStatusResult(
            repo_path=repo_path,
            clean=False,
            changed_files=[],
            error=f"git status timed out after {timeout}s",
        )

    if result.returncode != 0:
        logger.warning("%s: git status failed (not a repo?)", repo_path)
        return GitStatusResult(
            repo_path=repo_path,
            clean=False,
            changed_files=[],
            error=result.stderr.strip() or "not a git repository",
        )

    changed_files = [line for line in result.stdout.splitlines() if line.strip()]
    logger.info("%s: %d changed file(s)", repo_path, len(changed_files))
    return GitStatusResult(
        repo_path=repo_path, clean=not changed_files, changed_files=changed_files
    )


def git_log(
    repo_path: str, n: int = 5, *, timeout: float = DEFAULT_TIMEOUT
) -> list[str]:
    """Return the last `n` commits in `repo_path`, one `<sha> <subject>` line each.

    Uses `git log --oneline -n N`, the same stable one-line-per-commit
    format `git status --porcelain` uses for changed files. Returns an
    empty list -- never raises -- for a path that is not a git repository
    or a repository with no commits yet; both are normal, reportable
    outcomes, not exceptions.
    """
    logger.debug("reading last %d commit(s) in %s", n, repo_path)
    try:
        result = subprocess.run(
            ["git", "log", "--oneline", "-n", str(n)],
            capture_output=True,
            text=True,
            timeout=timeout,
            cwd=repo_path,
            check=False,
        )
    except FileNotFoundError:
        logger.warning("git is not installed or not on PATH")
        return []
    except subprocess.TimeoutExpired:
        logger.warning("%s: git log timed out after %.1fs", repo_path, timeout)
        return []

    if result.returncode != 0:
        logger.warning("%s: git log failed (not a repo, or no commits yet)", repo_path)
        return []

    return [line for line in result.stdout.splitlines() if line.strip()]


def docker_info() -> dict:
    """Run `docker info --format json` and return the parsed document.

    Returns a plain dict with at least an `"available"` key: `True` with
    the rest of Docker's own fields merged in when the daemon answered,
    `False` with an `"error"` key describing why otherwise -- Docker not
    installed, the daemon not running, or a response that was not valid
    JSON. Never raises: an operator asking "is Docker even up" needs an
    answer, not a stack trace.
    """
    logger.debug("checking docker info")
    try:
        result = subprocess.run(
            ["docker", "info", "--format", "json"],
            capture_output=True,
            text=True,
            timeout=DEFAULT_TIMEOUT,
            check=False,
        )
    except FileNotFoundError:
        logger.warning("docker is not installed or not on PATH")
        return {"available": False, "error": "docker is not installed or not on PATH"}
    except subprocess.TimeoutExpired:
        logger.warning("docker info timed out after %.1fs", DEFAULT_TIMEOUT)
        return {
            "available": False,
            "error": f"docker info timed out after {DEFAULT_TIMEOUT}s",
        }

    if result.returncode != 0:
        logger.warning("docker info failed -- daemon likely not running")
        return {
            "available": False,
            "error": result.stderr.strip() or "docker daemon is not reachable",
        }

    try:
        data = json.loads(result.stdout)
    except json.JSONDecodeError:
        logger.warning("docker info did not return valid JSON")
        return {"available": False, "error": "docker info did not return valid JSON"}

    data["available"] = True
    logger.info("docker daemon reachable")
    return data

Notice every one of the three subprocess.run() calls above passes a list of arguments, never a string, and never sets shell=True. Every one also passes an explicit timeout. Those two rules are non-negotiable in this file -- the Deep Dive shows exactly what breaks the moment either one is skipped. Every call also passes check=False explicitly: this project's ruff configuration flags a subprocess.run() call with no explicit check= argument, since leaving it out is an easy way to forget whether a non-zero exit should raise or not. check=False here documents the actual intent plainly -- these functions inspect result.returncode themselves and turn a failure into data, not an exception, so subprocess.run() must never raise on their behalf.

Then add this command next to health_check_many:

src/platformops/cli.py
@app.command("local-status")
def local_status(
    ctx: typer.Context,
    path: Annotated[
        Path,
        typer.Option(
            "--path", help="directory to inspect (defaults to the current directory)"
        ),
    ] = Path("."),
    as_json: Annotated[
        bool,
        typer.Option(
            "--json", help="print machine-readable JSON instead of plain text"
        ),
    ] = False,
) -> None:
    """Show local git and Docker state for a directory -- no network calls.

    Reports the git working tree state for `path` (or the current
    directory) and whether the Docker daemon is reachable. Always exits 0
    -- this command reports state, it does not judge it; a caller that
    wants to fail a pipeline on a dirty tree reads the `--json` output and
    decides that itself.
    """
    quiet = ctx.obj["quiet"]

    git_result = git_status(str(path))
    docker_result = docker_info()

    if as_json:
        typer.echo(
            json.dumps(
                {
                    "status": "ok",
                    "path": str(path),
                    "git": {
                        "clean": git_result.clean,
                        "changed_files": git_result.changed_files,
                        "error": git_result.error,
                    },
                    "docker": docker_result,
                },
                indent=2,
            )
        )
        raise typer.Exit(code=0)

    if git_result.error:
        typer.echo(f"git: {git_result.error}")
    elif not quiet or not git_result.clean:
        state = (
            "clean"
            if git_result.clean
            else f"{len(git_result.changed_files)} changed file(s)"
        )
        typer.echo(f"git: {state}")
        for line in git_result.changed_files:
            typer.echo(f"  {line}")

    if docker_result.get("available"):
        if not quiet:
            version = docker_result.get("ServerVersion", "unknown version")
            typer.echo(f"docker: reachable ({version})")
    else:
        typer.echo(f"docker: {docker_result.get('error', 'not reachable')}")

    raise typer.Exit(code=0)

Path and Annotated are already imported in cli.py from earlier modules, so nothing else needs to change there.

tests/test_local_ops.py
import json
import subprocess

from platformops.local_ops import docker_info, git_log, git_status


def _completed(returncode=0, stdout="", stderr=""):
    return subprocess.CompletedProcess(
        args=["fake"], returncode=returncode, stdout=stdout, stderr=stderr
    )


def test_git_status_reports_clean_for_no_changes(monkeypatch):
    monkeypatch.setattr(
        "platformops.local_ops.subprocess.run",
        lambda *a, **k: _completed(returncode=0, stdout=""),
    )

    result = git_status("/some/repo")

    assert result.clean is True
    assert result.changed_files == []
    assert result.error is None


def test_git_status_reports_changed_files(monkeypatch):
    monkeypatch.setattr(
        "platformops.local_ops.subprocess.run",
        lambda *a, **k: _completed(returncode=0, stdout=" M src/foo.py\n?? new.txt\n"),
    )

    result = git_status("/some/repo")

    assert result.clean is False
    assert result.changed_files == [" M src/foo.py", "?? new.txt"]

   subprocess safely (argument list, explicit timeout, explicit
   check=False, no shell=True) to search for unsafe subprocess usage
   elsewhere in the codebase. grep's own exit codes matter here: 0 means
   it found a match (this is NOT clean), 1 means no match was found
   (this IS clean), and 2 or higher is a real error (report it via the
   result's error field, not as a clean/not-clean answer). Return a
   dataclass ScanResult with clean: bool, findings: list[str], error:
   str | None = None. The check-security CLI command exits 0 when
   clean, exits 1 and prints every finding when shell=True is found, and
   calls _fail() with exit code 1 for a scan error (missing grep binary,
   timeout).

5. Add tests for container_list (mirroring the monkeypatch-on-
   subprocess.run pattern in tests/test_local_ops.py -- cover a normal
   multi-container response, an empty response, a response with one line
   that fails to parse mixed with lines that do parse, Docker
   unreachable, and Docker missing) and for scan_for_shell_true (a clean
   scan, a scan that finds one match, and a scan error). Add CLI tests
   for check-security in tests/test_cli.py (monkeypatching
   cli_module.scan_for_shell_true), covering both exit codes, and extend
   the existing local-status CLI tests to also monkeypatch
   container_list.

6. Do not add any new runtime dependency -- everything here uses only the
   standard library plus the already-installed git/docker/grep binaries.
   Run `uv run ruff check .` and `uv run pytest -q` yourself before you
   finish, and tell me the result.

This spec names every existing function signature exactly as it is in the project, states the NDJSON parsing detail and the grep exit-code contract explicitly (the same discipline every prior module's spec has insisted on), and asks for the same self-verification every agent step in this course has asked for.

Troubleshooting
  • git_status() or git_log() raises instead of returning a result. Confirm every subprocess.run() call in local_ops.py is wrapped in try/except for both FileNotFoundError and subprocess.TimeoutExpired -- a missing except clause is the usual cause of an unhandled crash where a graceful error result was expected.
  • docker_info() always reports unavailable, even though Docker Desktop is running. Confirm the actual flag is docker info --format json (not --format=json with a typo, and not the older docker info --format '{{json .}}' syntax, which some Docker versions still need) -- run the raw command yourself on the command line to see what your installed version expects.
  • container_list() crashes on a real docker ps response. This is almost always the NDJSON trap: docker ps --format json returns one JSON object per line, not one JSON array. A single json.loads(result.stdout) call over the whole output raises json.JSONDecodeError the moment there is more than one container running. Parse line by line instead.
  • check-security reports "clean" even after you added a shell=True line on purpose. Check scan_for_shell_true()'s handling of grep's exit codes -- exit code 0 means grep found a match, which is the opposite of "clean." A scanner that treats 0 as success (grep's normal meaning for "no error") instead of "found a hit" will report every real problem as clean.
  • A test in test_local_ops.py seems to actually run git or docker instead of using the monkeypatched fake. Confirm the patch target is the string "platformops.local_ops.subprocess.run" -- patching subprocess.run directly (without the module path) does not affect the subprocess.run call already imported inside platformops.local_ops.
  • uv run platformops local-status hangs instead of returning quickly. Confirm timeout= is actually being passed through to every subprocess.run() call, and that no code path in local_ops.py builds a command with shell=True -- a shell wrapping a command can itself hang in ways the bare command does not.
